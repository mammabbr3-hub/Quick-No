MOBILE DIGITAL HUB — UI UPDATE / MESSAGE RETENTION AUDIT

Applied rules:
1. Navigation/configuration/admin screens are edited in place when the action stays within the same screen/step.
2. Small changes such as ON/OFF, percentage adjustments, renaming, toggling, pagination, service/country configuration and similar screen actions reuse the current UI message.
3. When the user/admin deliberately leaves a step and enters a new flow, a fresh message is allowed.
4. Permanent tracking/result messages are NOT used as UI screens and are not auto-deleted or auto-edited. This includes IDs, OTPs, activation/order records, transaction/withdrawal/submission/support records, audit/result notifications and similar tracking messages.
5. The only generic deletion retained is the dedicated temporary “Please wait...” acknowledgement. It is removed when the real action starts.
6. Existing navigation-message auto-delete functions remain disabled.
7. Inline Back is used for in-place text-input screens; returning to Main Menu is treated as a deliberate step change and may create a fresh main-menu message.
8. Quick OTP “Get New Number” continues to create a separate permanent tracking message for the new activation because the old activation must remain independently trackable.

Additional issue found/fixed:
- Several admin panels were still calling send_message from callback actions, causing duplicate stacked screens. These were converted to in-place screen updates, including Feature Control, Admin Roles/Settings, Withdrawal Methods, Text/Menu Editor, Work/Mail option management, Custom Handles, Auto Messages, Fund Wallet Settings, and Quick OTP admin pricing/service screens.
- Text-entry prompts in those panels now reuse the active screen where safe; permanent result/record messages remain separate.
