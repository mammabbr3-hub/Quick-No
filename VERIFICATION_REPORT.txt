Hardening verified in this final build
---------------------------------------
1. PostgreSQL Work approve/reject uses GREATEST() rather than SQLite-only MAX(a,b).
2. User creation is atomic/idempotent across replicas.
3. Scheduled auto messages use distributed leases.
4. Audit-channel delivery uses per-row leases across replicas.
5. OTP price/stock refresh is single-leader across replicas.
6. Large broadcasts stream user IDs with keyset pagination instead of loading the
   full user table into memory.
7. Long broadcasts renew their distributed lease.
8. PostgreSQL migration resets BIGSERIAL sequences after copying explicit IDs.
9. Withdrawal payment-method handlers no longer depend on missing admin_menu().
10. Funding approval was hardened to claim the request before crediting the wallet,
    preventing concurrent admins from double-crediting the same request. The code
    no longer uses SQLite-only conn.total_changes on the PostgreSQL path.
11. Railway README/Procfile documentation now matches webhook/PostgreSQL production mode.
